# Project Statuses and Workflow

## Suggested project statuses

| Status | Meaning |
|---|---|
| Not started | Project has been recorded but work has not begun |
| In progress | Work is actively underway |
| On hold | Work is paused, with a reason recorded |
| Review | Output or milestone is awaiting review/approval |
| Completed | Agreed scope is complete |
| Cancelled | Project has been stopped |

## Suggested task statuses
- To do
- In progress
- Waiting
- Review
- Done
- Cancelled

## Suggested priority
- High — urgent or high-impact
- Medium — normal planned work
- Low — can be scheduled after higher-priority work

## Basic workflow
1. **Intake:** record the request, client, expected outcome, and received date.
2. **Planning:** define scope, tasks, owners, priorities, dependencies, and deadlines.
3. **Execution tracking:** update task statuses and record blockers.
4. **Review:** record reviewer, feedback, decision, and revision follow-up.
5. **Completion:** confirm deliverables and handover.
6. **Archive:** retain project records and links according to workspace policy.

## Tracking rules
- A project is not “on track” unless dates and current status support that conclusion.
- Mark overdue only when a due date exists and has passed.
- Do not calculate percentage completion unless a clear calculation method and task data exist.
- Record blockers with an owner and next action whenever known.
- Preserve a history of material status changes if the application supports it.
